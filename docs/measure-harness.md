# 計測ハーネス仕様（51D3 / A2E5のnext-action）

`51D3` の速度実測（紙 vs アプリ）を、拓男がストップウォッチと手書きメモでやらずに済むようにする。
**このプロダクトの続行・撤退を決める唯一の測定**なので、測定そのものが手間で歪まないことを最優先にする。

## 測るもの
1問ごとに次を記録する。

| 項目 | 取り方 |
|---|---|
| 所要時間 | アプリ内の開始/終了ボタン。**入力が60秒無かった区間は自動で除外しない**（考えている時間も解答時間のうち、が51D3の前提） |
| 打鍵数 | keydown のうちキーマップに割り当てのあるキーだけを数える。修飾キー単独は数えない |
| 立ち止まった回数 | **2秒以上キー入力が空いた回数**。B5E1の「速度を決めているのは打鍵数ではなく立ち止まる回数」仮説の実測値 |
| 使用キーマップ | A（素キー＝記号）/ B（逆レイヤー）。切替をログに残す |
| 紙の所要時間 | 手入力（分秒）。同じ節の**別問題**の値を入れる |
| 単元・出典 | 手入力（例: 青チャート数III 例題142） |

## 画面（3つだけ）
- **開始/終了**: 解答画面の端に1つ。押した瞬間から計測。終了で下のフォームが出る。
- **終了フォーム**: 紙の所要時間・出典・キーマップ・ひとことメモ。**紙時間は後から入れられる**（空で保存可）。
- **ログ一覧**: 1行1問。時間・打鍵数・立ち止まり数・紙時間・比率。**3問ごとの中央値と、1.2倍/1.5倍の線**を出す。

## 保存
- `localStorage` で足りる。1問1レコードのJSON配列。
- **JSONエクスポートを必ず付ける**。判定と分析はエクスポートしたデータで行う（アプリを壊しても測定結果が消えない）。

## やらないこと
- 集計グラフ、期間フィルタ、複数ユーザー、サーバ保存。判定に要らない。
- 計測の自動開始。押し忘れより誤検知のほうがデータを汚す。

## 実装上の注意
- 計測コードは**入力コアのイベント処理に割り込まない**。打鍵の遅延を作ったら測定対象そのものが変わる。
  keydown のリスナーは別に張り、記録はマイクロタスクへ逃がす。
- キーマップA/Bの切替は既に実行中差し替え可（`keymap.js`）。切替イベントをハーネスへ通知するだけでよい。
- テストは Playwright で「開始→打鍵N回→終了→保存レコードの打鍵数がN」を厳密照合する（既存 `tests/` の流儀に合わせる）。
