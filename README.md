# SHIKITYPE

数学の答案をPC上で入力し、複数のAIによる見直しを受けるためのWebアプリケーションです。

公開URL: https://shikitype.punoji.workers.dev

## 概要

SHIKITYPEは、大学受験の数学を対象に、紙とペンで行っていた途中式の記述と答案の見直しをPC上で完結させることを目指して制作しました。数式記号をキーボードから入力し、行形式またはキャンバス形式で答案を構成できます。完成前の答案を含め、AIが解法の方向性や計算の見直し箇所を示します。

## 開発背景

このアプリを制作したのには、主に3つの問題が私の勉強にあったからです。

1つ目は、「勉強がPCで完結しない」というものです。

どれだけYoutubeを活用したり問題をまとめるアプリを作ったりしても、紙とペンを使わなければ、問題を解くことができなかったんです。途中式を書く、見つけた条件を書く、回答を書く...みなまで言わずとも、数学の問題を解くなら、従来紙とペンは必須でした。ただ、この問題を解くという作業の中で、PCに移行できていなかったのは「紙とペンで書く」というだけだった。私は、ならばその部分も含めて「問題を解くためのアプリ」を一本化すれば良いじゃないか、という結論に達しました。


2つ目は、「自分の回答を精査することが難しい」というものです。

数学の問題を解いたことがある方なら、誰しも”自分の解法と答えの解法が違う”という経験があると思います（これは途中まで解けていたけれど、その先の解き方がわからなくなって答えを見る、といった場合も含む）。その時私の中では、自分が間違っていれば「この回答のどこで間違っていたんだろう？」という疑問が、自分が正解していれば「回答は合っていても、計算の過程は合っているのだろうか？」と言う疑問が生まれます。要するに、「自分の考えた解法の正誤」がわからない、というものです。これを吟味するのはものすごく難しいことで、私はこの作業に時間をかけすぎることで集中力が完全に途切れてしまい、勉強から手が離れてしまう、ということがよくありました。もう一度言いますが、ここで私が真に知りたがっているのはもはやその問題の単純な解法などではなく、「自分の考えていた解法を用いて解けるか、解けるとしてどうやれば解けるのか」です。また、その過程における自分の知らない公式や解法パターンも同時に知りたいのです。そしてこの問題は、自分の回答をAIに見てもらう、と言うことができれば解決するのでは？と言うところに繋がっていきます。

そこで出てくる3つ目の問題が、「AIに自分の解法を伝えることが難しい」というものです。

手書きかつ数学記号を用いた回答を読み取るのは、現在のOCRではほぼ不可能です。加えて私の解き方の癖として、紙の空白を埋め尽くすように式を書き込んでしまう、というものがありまして、あとから見ても自分で何が書いてあるかわからないほどにぐちゃぐちゃに書いてしまうんです。だからこそ、アプリに打ち込むという形をとることでAIにも理解しやすくなり、教えてもらいやすくなるのではないか？という考えに至ったのです。

## 設計方針

入力においては、打鍵数よりも「入力中に立ち止まる回数」を減らすことを優先しました。入力前に画面を見て確認する回数や、キーボードから手を離す回数を減らすことを目標としています。

- 構造を持つ数式は、括弧とEnterを用いて入力します。分数、上付き・下付き、根号、絶対値、積分、総和は、最も内側の未確定スロットを一段ずつ進める同一の操作規則で扱います。
- キーの割り当ては単元ごとに変えず、キーガイドのみを単元に合わせて切り替えます。単元を移っても同じ操作を継続できます。
- 変換入力では、ローマ字で読みや意味を入力すると数式記号の候補を表示します。候補はTab、矢印キー、Enterで選択・確定できます。読み辞書はCSVで入出力できます。

## 主な機能

- 数式の構造入力: 分数、上付き・下付き、根号、絶対値、積分、総和、極限などを入力できます。
- SHIKITYPE変換入力: 例として、`sigma`、`souwa`、`sekibun`、`integral`などから対応する候補を表示します。
- 文入力: 数式中に文章を記述するための文キーを備えています。
- 二つの編集面: 上から答案を書く行モードと、広い盤面へ式を配置するキャンバスモードを選択できます。
- ノート管理: 新規作成、履歴、削除、端末内保存、ログイン後のクラウド同期に対応しています。
- LaTeX書き出し: 数式ブロックのコピーとノート全体のLaTeXファイル出力に対応しています。
- 設定: 入力方式、キーガイド、単元、テーマ、読み辞書を設定できます。

## AIによる答案の見直し

答案を「見直す」と、OpenAI Responses APIを用いる四つの役割が順に検証します。独立した解法を作成する役割は、答案を参照せずに問題文と条件だけから検討します。続く役割が答案との照合、照合内容への反証、学習者に向けたヒントへの整理を担当します。

ちなみになのですが、正直、このアプリは複数エージェントを使おうというところからスタートしていません。なので、このアプリにいかにそれを落とし込んでいくかにはまだまだ試行錯誤の余地があると考えています。

| 段階 | 役割 | 内容 |
| --- | --- | --- |
| 1 | 解法担当 | 問題文と条件から、答案を見ずに解法を検討します。 |
| 2 | 照合担当 | 独立した解法と答案を照合し、見直す箇所を整理します。 |
| 3 | 反証担当 | 照合結果に見落としがないかを検討します。 |
| 4 | ヒント担当 | 答えを直接示さず、次に確かめる内容をヒントとしてまとめます。 |

画面には「AI同士の検証会話（要約）」として、四つの役割の受け渡しを確認できる形で表示します。独立解法や内部の詳細な出力をそのまま表示せず、学習に必要な要約だけを表示します。見直し結果の下では、そのヒントについて追加の質問を送れます。質問と回答は見直し結果とともに保存され、再読込後も確認できます。

## ローカルでの実行

### 必要な環境

- Node.js 22以降
- AIによる見直しとクラウド同期を実行する場合: npm、OpenAI APIキー

数式描画に使用するMathLiveは`vendor/`に含めています。数式の入力、端末内保存、LaTeX書き出しだけを確認する場合は、追加のパッケージインストールや環境変数は不要です。

### 最短で起動する

新しいディレクトリで、次の手順を実行してください。

```bash
git clone https://github.com/puppunosuke/shikitype.git
cd shikitype
node server.mjs
```

ブラウザで http://localhost:8893/app.html を開きます。静的サーバを終了するには、起動したターミナルでCtrl+Cを入力してください。

### AIによる見直しとクラウド同期を含めて起動する

Cloudflare WorkersとD1をローカルで起動します。まず`cloud/`へ移動し、依存関係をインストールします。

```bash
cd cloud
npm ci
```

次に、`cloud/.dev.vars`を作成して以下を設定してください。このファイルは秘密値を含むため、Gitへ追加しないでください。

```dotenv
AUTH_PEPPER=十分に長いランダム文字列
OPENAI_API_KEY=OpenAIのAPIキー
# Googleログインを有効にする場合だけ設定します。
# GOOGLE_CLIENT_ID=Google OAuthクライアントID
```

ローカルD1へ移行ファイルを適用し、Workerを起動します。

```bash
npx wrangler d1 migrations apply shikitype-db --local
npm run dev
```

ブラウザで http://localhost:8787 を開き、アカウントを作成またはログインしてからクラウド同期、AIによる見直し、追加質問を利用します。`AUTH_PEPPER`はログイン情報の保護に使う秘密値です。`OPENAI_API_KEY`を設定しない場合でもアプリケーションは起動しますが、AIによる見直しと追加質問は利用できません。Googleログインは`GOOGLE_CLIENT_ID`を設定し、Google OAuthのウェブクライアントに`http://localhost:8787`を許可した場合に利用できます。

## テスト

画面側のテストはPlaywrightで実ブラウザを操作します。新規clone後は、先にPlaywrightを含む依存関係をインストールしてください。

```bash
cd spike
npm ci
npx playwright install chromium
cd ..
```

別のターミナルでプロジェクト直下から`node server.mjs`を起動し、次を実行します。

```bash
node --test tests/*.test.mjs
```

Worker側は、`cloud/`で次を実行します。

```bash
npm ci
npm run check
```

`npm run check`は、静的アセットの生成、型検査、Workerのテストを実行します。AI APIへの実リクエストはテストでは送信せず、応答を模擬して四段階の入力範囲と出力形式を検証します。
