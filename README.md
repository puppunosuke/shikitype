# SHIKITYPE

**数学の問題を、紙とペンに戻らずにPCで解き切るためのエディタ。**
書いた答案は、そのまま複数のAIに検証させて「どこで、なぜ間違えたのか」を受け取れる。

公開URL: https://shikitype.punoji.workers.dev

---

## なぜ作ったか

作者は理系の受験生で、自分の勉強にあった3つの問題を解くために作った。

**1. 勉強がPCで完結しない。**
YouTubeを使おうと、問題をまとめるアプリを自作しようと、数学だけは紙とペンに戻らないと解けなかった。途中式を書く、見つけた条件を書く、答えを書く——問題を解くという作業の中で、PCへ移行できていなかったのは「紙とペンで書く」というその一点だけだった。ならばそこも含めて一本化すればいい。

**2. 自分の答案を精査するのが難しい。**
「自分の解法と模範解答の解法が違う」という経験は誰にでもある。そのとき本当に知りたいのは問題の解き方そのものではなく、**「自分が考えた解法で解けるのか、解けるならどう詰めるのか」**だ。これを自力で吟味するのは非常に難しく、時間を溶かして集中力ごと失う。

**3. AIに自分の解法を伝えるのが難しい。**
手書き＋数学記号は、現在のOCRではほぼ読み取れない。加えて作者には「紙の空白を埋め尽くすように式を書く」癖があり、後から自分で見ても判読できない。最初からアプリへ打ち込む形にすれば、AIにも渡せる。

## 設計の中心にあるもの

### 立ち止まる回数を、打鍵数より優先する

このプロダクトの唯一のデザインプリンシプルは次の一文。

> **入力中に立ち止まる回数を、打鍵数・表示の正しさ・機能の網羅・見た目の完成度より優先する。**

守るのは「打つ前に画面を見て確認する必要がないこと」「手がホームポジションから外れないこと」「マウスに触らせないこと」。
**打鍵が1回増えても、手が止まらなくなるなら増やす。**

この原則は一度実際に方針を覆している。当初は「分数を書くとき、`a+b+c` まで打ってから `/` を押し、矢印キーで分子の範囲を遡って選ぶ」という打鍵数最小の方式だった。しかしこれは*その場で画面を見て範囲を選ぶ*ので手が止まる。そこで括弧で先に項を宣言する方式へ全面変更した。打鍵は増えるが無思考で打てる。**速度を決めているのは打鍵数ではなく停止回数**、という判断。

### 項システム

`()` を押すと括弧が開き、閉じると囲まれた範囲が1つの**項**になる。分数・上付き・下付き・根号・絶対値も同じ形で、押すとスロットが開き、閉じると外へ出る。

規則は1本だけ：**最も内側の未確定スロットを1段だけ閉じる**。例外を作らない。「この場合は〜」が増えると、打つ前に考える必要が生まれる＝原則違反になるため。

### キー割り当ては全単元で固定

単元プリセットが切り替えるのは**キーガイドの表示内容だけ**で、キーの割り当ては動かさない。割り当てが単元ごとに変わると、単元を移るたびに手が覚え直しになるからだ。

**表示は学習の補助輪、割り当ては一生モノ。**

### 専用IME（変換入力）

システム標準の日本語入力を遮断し、物理キーの打鍵を読みへ変換して数式記号の候補を出す独自のIMEを持つ。「しぐま」「そうわ」「すうれつのわ」のいずれからでも Σ が引ける。候補は編集中のブロック直下に出て、Tab/矢印で選び、Enterで確定する。

辞書は**現行の日本の高校数学の範囲**に限定している。範囲外の記号を候補へ混ぜないことと、範囲内のものが抜けていないことの両方を満たすのが方針。辞書はCSVで書き出し・読み込みでき、アカウントごとに持ち運べる。

## AIによる見直し

答案を書いたら「見直す」を押すと、4つの役割を持つAIが順に検証する。

| 段階 | 役割 | 渡されるもの |
|---|---|---|
| 独立した解法を作成 | 答案を見ずに自力で解く | 問題文と条件のみ |
| 答案と照合 | 自力解と答案を突き合わせる | 参照解と答案 |
| 診断を再検証 | 前段の判断に反証を試みる | 要約のみ |
| 最小のヒントに整理 | 安全な範囲だけをヒントにする | 該当箇所と方向性の要約のみ |

**答えを直接与えない設計になっている。** 最終段（ヒント生成）には問題文も模範解答も渡らず、「どのブロックが、どの種類の誤りか、どの方向へ考えるべきか」の要約だけが渡る。これはサーバ側のテストで契約として固定されている。

実際の出力例（平方完成の符号ミスを含む答案に対して）：

> **直す箇所**：平方完成後の式を一度展開し、元の関数の定数項と一致するか確認しましょう。定数項がずれると、値域の結論もずれます。
>
> **次の一手**：定数項を直した後、頂点が定義域に入るかを確認し、入るなら頂点と両端点の値を比較してください。

答えの数値は出さず、間違えた行を名指しして、自分で確かめる方法を示す。**解法暗記で終わらせないため。**

所要時間は本番実測で約15秒（4段階の合計）。待っている間はどの役割が動いているかが画面に表示され、閉じて別の作業をしても処理は続く。

## 主な機能

- **2つの編集面** — 行モード（上から書き下す）とキャンバスモード（紙のように2次元に配置）
- **取り消し・やり直し** — Ctrl+Z / Ctrl+Shift+Z。行モードとキャンバスで1本の履歴
- **再変換** — 変換を確定した直後のBackspaceで読みへ戻る（通常の日本語入力と同じ指運動）
- **ブロック操作** — Alt+ドラッグで複製、Shift+ドラッグで矩形選択、Ctrl+C/V
- **ノート管理** — 名前・絞り込み・ゴミ箱（削除は取り消せる）
- **LaTeXで書き出し** — ブロック単位のコピー、ノート全体の `.tex` ダウンロード
- **クラウド同期** — ログインすると別の端末からも開ける
- **5つのテーマ** — 国際数学誌編集室／文庫の未来／光学実験台／未来の資料室／数式美術館

## 動かし方

### 必要なもの

- [Node.js](https://nodejs.org/) 18以上

外部ライブラリのインストールは不要。数式描画に使う [MathLive](https://cortexjs.io/mathlive/) は `vendor/` に同梱してある。

### ローカルで動かす（最短）

```bash
git clone https://github.com/puppunosuke/shikitype.git
cd shikitype
node server.mjs
```

ブラウザで http://localhost:8893/app.html を開く。
これだけで数式の入力・ノートの保存（ブラウザ内）・LaTeXの書き出しまで動く。**AIの見直しとクラウド同期にはサーバ側の準備が必要**（下記）。

### AIの見直しとクラウド同期も動かす

Cloudflare Workers と D1（データベース）を使う。

```bash
cd cloud
npm install

# ローカル用のデータベースを作る
npx wrangler d1 migrations apply shikitype-db --local

# APIキーを置く（このファイルはgit管理外）
echo 'OPENAI_API_KEY=sk-...' > .dev.vars

npx wrangler dev --local
```

http://localhost:8787 で、ログイン・クラウド保存・AIの見直しまで含めて動く。

### テストを走らせる

```bash
# 画面側（Playwrightで実ブラウザを操作する）
node server.mjs &
node --test tests/*.test.mjs

# サーバ側（型検査＋テスト）
cd cloud && npm run check
```

画面側のテストは実際にブラウザを起動してキーを打ち、座標を測って検証する。**スクリーンショットの比較ではなく実測**にしているのは、この種の不具合が見た目では出ないため。

## 構成

```
app.html / app.js / styles.css   画面本体（バニラJS、ビルドツールなし）
conversion.js                    専用IMEの変換コア（DOM非依存）
keymap.js                        キー割り当てと単元定義
dictionary-table.js              読み辞書の表エディタ
unicode-latex.js                 Unicode記号 → LaTeX の変換表
server.mjs                       ローカル配信用の静的サーバ
vendor/                          MathLive（同梱）
cloud/                           Cloudflare Worker（認証・同期・AI見直し）
  src/index.ts                   APIとAIの4段パイプライン
  migrations/                    データベースの移行
tests/                           画面側のテスト
tools/                           読み辞書CSVエディタ（単体HTML）
docs/                            計測方法などのメモ
```

ビルドツールを使っていない。ライブラリの実体は `vendor/` に置き、`<script type="module">` で直接読む。ソースを開けばそのまま動いているコードが読める状態を保つため。

## 現時点での制約

正直に書いておく。

- **AIの見直しにはログインが必要**（答案をサーバへ送るため）
- **反証の段階が実際に前段の誤りを覆した実例は、まだ確認できていない。** 4段階すべてが動くことと、各段が独自に再導出していることは実測で確認済みだが、照合が誤っていて反証がそれを正す場面は再現できていない
- **画像での書き出しは未対応。** 専用フォントとshadow DOMの組み合わせで描画結果を画像化できず、新しいライブラリの導入が必要になるため見送った。LaTeXのテキストでは書き出せる
- 入力速度が紙と比べてどうかの実測は、まだ十分な数を取れていない。このプロダクトは**「紙と同等以上の速度」が中心的な主張**なので、ここが崩れたら他が全部できても成立しない、という位置づけで撤退線を引いてある
